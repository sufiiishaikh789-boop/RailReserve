# Risk Register — Railway Reservation System (Team 11)

Risk ratings: Likelihood (1=Low, 2=Medium, 3=High) × Impact (1=Low, 2=Medium, 3=Critical) = Risk Score.

| Risk ID | Risk Description | Category | Likelihood | Impact | Score | Mitigation Strategy | Contingency | Owner |

| **R-01** | Two simultaneous requests book the last available seat (race condition / phantom read) | Technical | 3 | 3 | **9** | Use `BEGIN IMMEDIATE` SQLite transactions + `UPDATE ... WHERE available_seats > 0` + rows-affected check. Automated concurrent test in CI. | If overbooking detected in test: upgrade isolation level, add row-level lock emulation via separate `booking_locks` table. | Developer |
| **R-02** | Duplicate form submission creates two bookings for same passenger (double charge) | Technical | 2 | 3 | **6** | Generate `idempotency_key` on client before first request; enforce `UNIQUE` constraint in DB; server returns 200 for repeat submissions. | Deploy exponential back-off retry logic on frontend; audit logs track all submission IDs. | Developer |
| **R-03** | Payment failure incorrectly marks booking as CONFIRMED | Technical | 1 | 3 | **3** | Booking state machine: `CONFIRMED` state only reachable from payment callback with `SUCCESS` status. DB transaction rolls back on failure. Explicit test: TC-14. | Automated regression test blocks any code path that writes `CONFIRMED` before payment verification. | Developer |
| **R-04** | Inconsistent booking state after partial transaction failure (DB write interrupted) | Technical | 2 | 3 | **6** | All multi-step operations wrapped in single SQLite transaction. Failed transactions automatically rolled back by SQLite engine. | Manual recovery script (`scripts/audit-consistency.ts`) to detect and flag orphaned pending bookings. | Developer |
| **R-05** | Unauthorized access to administrator routes | Security | 2 | 3 | **6** | JWT middleware on ALL `/api/admin/*` routes. Frontend hiding of admin buttons is explicitly insufficient — server enforces independently. Automated TC-24. | Rate limiting on `/api/admin/login`; bcrypt password hashing (cost 12); rotate JWT secret in `.env`. | Developer |
| **R-06** | Data exposure: passenger records accessible without authorization | Security | 2 | 2 | **4** | Booking lookup requires matching contact email OR phone. No public endpoint lists all bookings. Admin-only views of full reservation list. | Add per-booking OTP verification in future enhancement. | Developer |
| **R-07** | SQLite file corruption on abrupt process termination | Technical | 1 | 3 | **3** | SQLite WAL journal mode enabled.
